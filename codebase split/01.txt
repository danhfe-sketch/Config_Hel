# Guide to Implementing New Parameters

This guide provides a step-by-step process for adding new parameters to the LT32Pro Configurator application. Following these steps will ensure that the new parameter is correctly integrated into the UI, the bulk read/write operations, and the individual command sending.

## 1. Update `Parameter UI List.md`

The `Parameter UI List.md` file is the source of truth for the UI generation. It defines the structure of the parameters, their UI elements, and their commands.

To add a new parameter, you need to add a new `### Config` section to this file. The section should contain the following information:

- `name`: The name of the parameter.
- `label`: The label that will be displayed in the UI.
- `ui_element`: The type of UI element to use (e.g., `dropdown`, `text_input`, `toggle_switch`).
- `options`: A list of options for dropdowns and toggle switches.
- `commands`: The `set` and `read` commands for the parameter.

**Example:**

```markdown
### Config: Distance Movement Action

*   **name:** distance_movement_action
*   **label:** "Configurar a├º├úo para movimento por dist├óncia"
*   **ui_element:** "dropdown"
*   **options:** ["Automaticamente ativado ap├│s entrar no modo DEFENSE (quando a igni├º├úo ├® desligada)", "Envia um alerta - Apenas uma vez independente da IGN on ou off", "Envia um alerta uma vez e bloqueia o ve├¡culo - Apenas uma vez independente da IGN on ou off"]
*   **commands:**
    *   **set:** `SZCS#MOVEALMFUN=X` (Note: X=0 for the first option, 1 for the second, 2 for the third)
    *   **read:** `CXCS#MOVEALMFUN`
```

## 2. Update `services/parameter_specification.py`

The `services/parameter_specification.py` file contains the hardcoded representation of the `Parameter UI List.md` file. You need to add the new parameter to the `PARAMETER_SPECIFICATION` and `COMMAND_VALUE_MAPPINGS` dictionaries in this file.

### `PARAMETER_SPECIFICATION`

Add the new parameter to the appropriate section in the `PARAMETER_SPECIFICATION` dictionary. The structure of the parameter should match the one in the `Parameter UI List.md` file.

**Example:**

```python
'distance_movement_action': ParameterConfig(
    name='distance_movement_action',
    label='Configurar a├º├úo para movimento por dist├óncia',
    ui_element='dropdown',
    options=['Automaticamente ativado ap├│s entrar no modo DEFENSE (quando a igni├º├úo ├® desligada)', 'Envia um alerta - Apenas uma vez independente da IGN on ou off', 'Envia um alerta uma vez e bloqueia o ve├¡culo - Apenas uma vez independente da IGN on ou off'],
    commands={
        'set': 'SZCS#MOVEALMFUN=X',
        'read': 'CXCS#MOVEALMFUN'
    }
)
```

### `COMMAND_VALUE_MAPPINGS`

If the parameter uses a dropdown or a toggle switch, you need to add a mapping from the UI options to the command values in the `COMMAND_VALUE_MAPPINGS` dictionary.

**Example:**

```python
'distance_movement_action': {
    'Automaticamente ativado ap├│s entrar no modo DEFENSE (quando a igni├º├úo ├® desligada)': 0,
    'Envia um alerta - Apenas uma vez independente da IGN on ou off': 1,
    'Envia um alerta uma vez e bloqueia o ve├¡culo - Apenas uma vez independente da IGN on ou off': 2
},
```

## 3. Update `services/configuration_reader_service.py`

The `services/configuration_reader_service.py` file is responsible for reading the device configuration. You need to update this file to include the new parameter in the bulk read operation.

### `_init_parameter_query_commands`

Add the new parameter to the `parameter_query_commands` dictionary. This will include the parameter in the list of commands to be executed during a bulk read.

**Example:**

```python
'distance_movement_action': ('MOVEALMFUN', 'get_distance_movement_action'),
```

### `_init_response_patterns`

Add a new regex pattern to the `response_patterns` dictionary to parse the response for the new parameter.

**Example:**

```python
'get_distance_movement_action': r'READOK:\s*MOVEALMFUN=(\d+)',
```

### `_get_command_type_for_parameter`

Add a new entry to the `command_type_mapping` dictionary to map the parameter name to the command type.

**Example:**

```python
'distance_movement_action': 'get_distance_movement_action',
```

### `parse_device_response`

Add a new `elif` block to the `parse_device_response` method to handle the parsing of the new parameter's response. This block will map the numeric value from the response to the corresponding UI option.

**Example:**

```python
elif command_type == 'get_distance_movement_action':
    action_map = {'0': 'Automaticamente ativado ap├│s entrar no modo DEFENSE (quando a igni├º├úo ├® desligada)', 
               '1': 'Envia um alerta - Apenas uma vez independente da IGN on ou off', 
               '2': 'Envia um alerta uma vez e bloqueia o ve├¡culo - Apenas uma vez independente da IGN on ou off'}
    action_value = match.group(1)
    parsed_values['distance_movement_action'] = action_map.get(action_value, action_value)
```

## 4. Update `services/lt32pro_command_formatter.py`

The `services/lt32pro_command_formatter.py` file is responsible for formatting the commands before they are sent to the device. If the new parameter uses a `CXCS` read command, you need to add it to the `READ_COMMAND_MAPPINGS` dictionary.

**Example:**

```python
'MOVEALMFUN': 'CXCS#MOVEALMFUN',
```

## 5. Update `ui/parameters_frame.py`

The `ui/parameters_frame.py` file is responsible for creating and managing the UI elements for the parameters. You need to add the new parameter to the `_get_ui_parameter_mapping` method to map the parameter to the UI.

**Example:**

```python
'distance_movement_action': {'section': 'movement_alerts', 'parameter': 'distance_movement_action'},
```

## 6. Update `services/device_command_mapper.py`

The `services/device_command_mapper.py` file is responsible for generating the bulk write commands. You need to add the new parameter to the `individual_params` list in the `get_bulk_commands` method.

**Example:**

```python
'distance_movement_action'
```

You also need to add a new method to format the command and add it to the `individual_mapping` dictionary in the `_generate_individual_command` method.

**Example:**

```python
def format_distance_movement_action_command(self, value: str) -> str:
    """Format distance movement action configuration command."""
    # Map distance movement action to command value
    distance_movement_action_mapping = {
        'Automaticamente ativado ap├│s entrar no modo DEFENSE (quando a igni├º├úo ├® desligada)': '0',
        'Envia um alerta - Apenas uma vez independente da IGN on ou off': '1',
        'Envia um alerta uma vez e bloqueia o ve├¡culo - Apenas uma vez independente da IGN on ou off': '2'
    }
    
    value_code = distance_movement_action_mapping.get(value, '0')
    command = f"ATSMS:SZCS#MOVEALMFUN={value_code}"
    
    if hasattr(self, 'command_validation_gateway') and self.command_validation_gateway:
        try:
            self.command_validation_gateway.validate_command(command, source="bulk_commands")
        except ValueError as e:
            raise ValueError(f"Distance movement action command validation failed: {str(e)}")
    return command

'distance_movement_action': lambda v: self.format_distance_movement_action_command(v)
```

## 7. Update `services/parameter_specification_factory.py`

The `services/parameter_specification_factory.py` file is responsible for creating the UI elements and handling the individual send button actions. You need to add a new `_send_*_command` method and call it from `_send_parameter_command`.

**Example:**

```python
def _send_distance_movement_action_command(self, values: dict):
    """Send distance movement action configuration command"""
    distance_movement_action = str(values.get('distance_movement_action', '')).strip()
    
    # Map distance movement action to command value
    distance_movement_action_mapping = {
        'Automaticamente ativado ap├│s entrar no modo DEFENSE (quando a igni├º├úo ├® desligada)': '0',
        'Envia um alerta - Apenas uma vez independente da IGN on ou off': '1',
        'Envia um alerta uma vez e bloqueia o ve├¡culo - Apenas uma vez independente da IGN on ou off': '2'
    }
    
    value = distance_movement_action_mapping.get(distance_movement_action, '0')
    command = f"ATSMS:SZCS#MOVEALMFUN={value}"
    
    self.serial_service.send_command(command, command_type='distance_movement_action')
    messagebox.showinfo(
        self.i18n_service.get("success", "Success"),
        self.i18n_service.get("distance_movement_action_sent", "Distance movement action configuration sent to device")
    )

elif param_name == 'distance_movement_action':
    self._send_distance_movement_action_command(param_values)
```

## Conclusion

By following these steps, you can successfully add a new parameter to the LT32Pro Configurator application. It is important to pay attention to the details and ensure that the new parameter is correctly integrated into all the relevant files.

# Product Requirements Document: LT32Pro Device Configurator v1

## 1. Introduction

This document outlines the product requirements for the "LT32Pro Device Configurator v1," a desktop application for Windows 11. This software serves as the primary interface for technicians and administrators to configure, monitor, and manage LT32Pro tracking hardware. It modernizes the existing `LT32Pro Configurator` by introducing an updated user interface, improved usability, and robust features, ensuring a seamless experience on the Windows 11 platform.

**Target Audience:**
*   Field Technicians
*   System Administrators
*   Support Staff

## 2. Vision and Goals

**Vision:** To provide a modern, intuitive, and reliable tool for configuring LT32Pro hardware, improving technician efficiency and reducing configuration errors.

**Business Goals:**
*   Modernize the existing application to align with current UI/UX standards.
*   Ensure compatibility and stability with the Windows 11 operating system.
*   Provide a platform for future feature enhancements.
*   Enable branding and customization options for partners.

**User Goals:**
*   Quickly and easily connect to a device.
*   Clearly view the current device configuration.
*   Modify and send single or multiple configuration parameters reliably.
*   Monitor the device's real-time communication log.
*   Save and load common configuration profiles.
*   Access necessary drivers and manuals directly from the application.

## 3. Target Platform

*   **Operating System:** Windows 11
*   **Framework:** Python with a suitable GUI toolkit (e.g., Tkinter, PyQt, or Kivy).

## 4. Features and Requirements

### 4.1. Core Functionality: Device Management

#### 4.1.1. Serial (COM) Port Communication
*   **Requirement:** The application must automatically detect and list available COM ports.
*   **Requirement:** Users must be able to manually select a COM port from the list.
*   **Requirement:** A clear visual indicator must show the connection status (e.g., Connected/Green, Disconnected/Red).
*   **Requirement:** The application must gracefully handle connection errors (e.g., device unplugged).

#### 4.1.2. Device Configuration
*   **Requirement:** The UI must provide intuitive controls for all device parameters seen in the v3.19 screenshot. This includes:
    *   Numeric inputs (Vibration, Timers, Sensitivity)
    *   Dropdowns (Heart Beat, Curve Sensor)
    *   Radio buttons (Transmission Mode, Lock Type, Ignition Type, Protocol, Timezone)
    *   Text inputs (APN, IP/DNS, Port)
*   **Requirement:** Each parameter must have an "Enviar" (Send) button to update the setting on the device individually.
*   **Requirement:** The application must validate user input to prevent errors (e.g., ensure values are within the specified range).

#### 4.1.3. Bulk Commands & Device Actions
*   **Requirement:** The following global actions must be available as buttons:
    *   **Enviar todos os comandos:** Sends all currently displayed settings to the device.
    *   **Checar configura├º├úo:** Reads the current configuration from the device and populates the UI fields.
    *   **Reiniciar equipamento:** Sends a command to reboot the device.
    *   **Reset de f├íbrica:** Sends a command to restore the device to its factory default settings. A confirmation dialog must be shown before proceeding.

#### 4.1.4. Serial Log & Custom Commands
*   **Requirement:** A dedicated, scrollable text area shall display the real-time serial communication log between the application and the device.
*   **Requirement:** The log must be clear and easy to read, with options to copy or export the log to a text file.
*   **Requirement:** A "Comando Livre" (Free Command) input field and "Enviar" button must be provided for sending custom or diagnostic commands to the device.

### 4.2. User Interface & Experience

#### 4.2.1. Main Window
*   **Requirement:** The application will have a modern, clean UI following Windows 11 design principles (e.g., Mica/Acrylic effects, rounded corners).
*   **Requirement:** The layout will be organized logically, grouping related settings into sections as in the original design.
*   **Requirement:** The application window must be resizable, with content adapting gracefully to different sizes.
*   **Requirement:** The IMEI and ICCID of the connected device should be clearly displayed when available.

#### 4.2.2. Toolbar
*   **Requirement:** A toolbar at the top of the application will provide access to higher-level functions:
    *   **Perfis de Configura├º├úo (Configuration Profiles):** Dropdown to save the current settings as a named profile or load a previously saved profile.
    *   **Idioma (Language):** Dropdown to switch the UI language (e.g., Portuguese, English, Spanish).
    *   **Ajuda (Help):** Dropdown with links to:
        *   Install/Update `Driver Cabo de Configura├º├úo` (Configuration Cable Driver).
        *   Open `Manuais de Equipamentos` (Equipment Manuals - PDF or web link).
    *   **Restaurar Padr├Áes (Restore Defaults):** Resets the UI fields to the application's default values (not the device's factory settings).
    *   **Personaliza├º├úo (Personalization):** Opens a settings dialog for app customization.

### 4.3. Advanced Features

#### 4.3.1. Configuration Profiles
*   **Requirement:** Users must be able to save the complete set of on-screen configurations as a local file (`.lt32config`).
*   **Requirement:** Users must be able to load a `.lt32config` file to populate the UI instantly.

#### 4.3.2. Internationalization
*   **Requirement:** The application must support multiple languages. At a minimum, Portuguese, English, and Spanish will be included. The default language will be Portuguese.

#### 4.3.3. Customization & Branding
*   **Requirement:** A "Personalization" screen, accessible from the toolbar, will allow users/partners to customize the application's appearance.
*   **Requirement:** The Personalization screen shall provide the following options:
    *   **Theme Selection:**
        *   An option to choose between "Light", "Dark", and "System" themes.
        *   The theme change will be applied instantly without requiring an application restart.
        *   The selected theme will be saved and applied on subsequent launches.

## 5. Non-Functional Requirements

*   **Performance:** The application must be responsive, with no noticeable lag during UI interaction or device communication.
*   **Reliability:** The application must be stable and handle unexpected device disconnections or communication errors without crashing.
*   **Usability:** The tool should be intuitive enough for a new technician to use with minimal training.

## 6. Assumptions and Dependencies

*   The user's system has the necessary permissions to install device drivers (for the configuration cable).
*   The application relies on external libraries specified in `requirements.txt`. These libraries, such as `customtkinter`, `pyserial`, and `pyperclip`, must be installed in the Python environment.
*   The device communicates over a standard serial (COM) port at a default baud rate of 9600.

## 7. Revision History

| Version | Date       | Author(s)          | Changes                                                                                                        |
| :------ | :--------- | :----------------- | :------------------------------------------------------------------------------------------------------------- |
| 1.0.0   | 2023-10-27 | Gemini Code Assist | Initial version of the PRD. Defines core functionality for device connection, configuration, logging, and UI/UX. |
| 1.0.1   | 2023-10-27 | Gemini Code Assist | Added details to Customization & Branding. Added Assumptions and Revision History sections.                      |

## 8. Distribution

*   **Requirement:** The application must be packaged as a single, standalone executable file for Windows 11 (e.g., using PyInstaller or a similar tool). This executable should not require any external dependencies or a separate Python installation on the user's machine.

# Al Input: Ul and Command Specification for LT32 PRO

This document provides a structured specification of the user interface components and corresponding device commands for the LT32 PRO configurator. It is designed to be parsed by an Al for tasks like automated Ul generation or command scripting.

## Section: Network Parameters

### Config: APN Settings

*   **name:** apn_settings
*   **label:** "Configura├º├úo APN"
*   **description:** "Configures the APN, username, and password for the mobile network."
*   **fields:**
    *   **field_1:**
        *   **name:** apn
        *   **label:** "APN"
        *   **ui_element:** "text_input"
        *   **validation:** "Accepts a standard APN name, an IP address, or a URL."
    *   **field_2:**
        *   **name:** user
        *   **label:** "Usu├írio"
        *   **ui_element:** "text_input"
    *   **field_3:**
        *   **name:** password
        *   **label:** "Senha"
        *   **ui_element:** "text_input"
*   **commands:**
    *   **set:** `APN,<apn>,<user>,<password>#`
    *   **read:** `APN#`

### Config: Server Settings

*   **label:** "Configura├º├úo de Servidor"
*   **description:** "Configures the primary server IP/URL and port."

# LT32Pro Device Configurator v1

This is a desktop application for Windows 11 to configure, monitor, and manage LT32Pro tracking hardware, as specified in the Product Requirements Document.

## Setup

1.  Ensure you have Python 3.8+ installed.
2.  Create a virtual environment:
    ```sh
    python -m venv venv
    .\venv\Scripts\activate
    .\venv\Scripts\activate.bat
    ```
3.  Install the required dependencies:
    ```sh
    pip install -r requirements.txt
    ```
4.  Run the application:
    ```sh
    python main.py
    ```

## Running Tests

The application includes comprehensive integration tests to verify all functionality:

1. Make sure you have completed the **Setup** steps above.
2. Run specific test files that don't involve GUI components:
   ```sh
   python -m unittest test_app_config_service.py test_language_persistence.py test_theme_persistence.py
   ```
3. Run a specific test method:
   ```sh
   python -m unittest test_integration.IntegrationTest.test_language_switching_integration
   ```

### Available Tests

- `test_integration.py`: Comprehensive integration tests for the entire application
- `test_theme_persistence.py`: Tests theme switching persistence across application restarts
- `test_language_persistence.py`: Tests language switching persistence across application restarts
- `test_app_config_service.py`: Tests the centralized configuration service
- `test_all_radio_parameters.py`: Tests radio button parameters functionality
- `test_dropdown_ui.py`: Tests dropdown parameters functionality
- `test_numeric_parameters.py`: Tests numeric parameters functionality
- `test_operation_confirmation.py`: Tests operation confirmation dialogs and progress indicators
- `test_connection_error_handling.py`: Tests connection error handling and recovery
- `test_build_configuration.py`: Tests PyInstaller build configuration

## Building a Standalone Application

To create a single executable file for distribution on Windows 11 (as per PRD section 8), follow these steps:

1. Make sure you have completed the **Setup** steps above, which includes installing `pyinstaller`.
2. Run the build script from the project's root directory:

   ```sh
   # Activate the virtual environment first
   .\venv\Scripts\activate
   
   # Install PyInstaller if not already installed
   pip install pyinstaller
   
   # Run PyInstaller
   python -m PyInstaller --name="LT32Pro_Configurator_v1" --windowed --onefile --add-data "assets;assets" main.py
   ```

   python build_with_icon.py

   Command options explained:
   * `--name`: Sets the name of the executable.
   * `--windowed`: Prevents a console window from appearing when the application is run.
   * `--onefile`: Packages everything into a single executable.
   * `--add-data "assets;assets"`: Bundles the `assets` directory (containing locales and images) into the application.

3. Alternatively, you can use the provided batch file:

   ```sh
   # Edit build_app.bat to ensure it has the correct Python path
   # Then run:
   .\build_app.bat
   ```

4. The standalone application will be located in the `dist` directory.

### Troubleshooting Build Issues

If you encounter issues with PyInstaller:

1. Make sure you're running the command from the activated virtual environment
2. Try using the full Python module path: `python -m PyInstaller` instead of just `pyinstaller`
3. Check that all required modules are listed in the `hiddenimports` section of the spec file
4. If using a spec file, ensure it includes the new `app_config_service` module
5. For permission issues, try running the command prompt or PowerShell as administrator

### Known Issues with the Packaged Application

#### Language Setting Not Persisting

If the packaged application defaults to Spanish and doesn't save the language setting:

1. Use the fixed spec file: `LT32Pro_Configurator_v1_fixed.spec`
2. Build with console mode enabled for debugging: 
   ```
   python -m PyInstaller LT32Pro_Configurator_v1_fixed.spec
   ```
3. Check the console output for any errors related to configuration file access
4. If the issue persists, try running the executable as administrator once to create the configuration directory
5. Alternatively, manually create the `.lt32pro_config` directory in your user home folder and ensure it has write permissions

#### Configuration File Location

The application tries to save configuration in the following locations (in order):

1. `~/.lt32pro_config/app_config.json` (User's home directory)
2. In the same directory as the executable (fallback if home directory is not writable)

If you're experiencing issues with settings not being saved, check these locations for the configuration file and ensure the application has write permissions.

from PIL import Image, ImageDraw, ImageFont
import os

def create_splash_screen(version_text, master_image_path, output_path):
    """
    Adds a version text to a master splash screen image.

    Args:
        version_text (str): The version text to display on the splash screen.
        master_image_path (str): The path to the master splash screen image.
        output_path (str): The path to save the generated image.
    """
    try:
        # Open the master image
        image = Image.open(master_image_path).convert("RGBA")
        draw = ImageDraw.Draw(image)

        # Font settings
        try:
            font = ImageFont.truetype("arial.ttf", 35)
        except IOError:
            font = ImageFont.load_default()

        # Text color
        text_color = (255, 255, 255, 255)  # White

        # Position for the version text (centered)
        text_bbox = draw.textbbox((0, 0), version_text, font=font)
        text_width = text_bbox[2] - text_bbox[0]
        text_height = text_bbox[3] - text_bbox[1]
        x = (image.width - text_width) / 2
        y = (image.height - text_height) / 2 + 100  # Adjust Y position as needed

        # Draw the version text
        draw.text((x, y), version_text, font=font, fill=text_color)

        # Save the image
        image.save(output_path, "PNG")
        print(f"Splash screen saved to {output_path}")

    except FileNotFoundError:
        print(f"Error: Master splash image not found at '{master_image_path}'")
    except Exception as e:
        print(f"An error occurred: {e}")

if __name__ == "__main__":
    version = "1.3.4"
    master_image = "Master_splash.png"
    output_image = "splash.png"
    create_splash_screen(f"Version {version}", master_image, output_image)
